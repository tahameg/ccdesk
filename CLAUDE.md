# ccdesk — notes for agents

Electron app (UI Turkish, code English; formerly "Kurgu Masası": old `kurgu.json` projects and `~/.config/kurgu-masasi` are renamed on first sight) + an MCP server over the same project folders. A desk for deciding a video edit, not a video editor (owner, 2026-11-14).

Model (format 2): **scripts** `{id, time, text}` — spoken text, one flow: array order is the truth, `time` is laid back to back from 0 after every op and on load (no gaps, no overlaps; older projects close up in their order); length = `tokenize(text, settings).duration` (never stored); events move with the script being said at them (store.js `reflow`); `[…]` = direction for the AI (not read), `/n` = n silence units (`/` alone = 1). **events** `{id, time, title, text, media[]}` — moments. **suggestions** `{id, summary, ops, status}` — Claude proposes, the owner decides in the app. No comments, no ranges (format 1 projects are converted on load).

- Project settings include `language` (content language, `tr` | `en`, a string in `settings`; `setSettings` validates it): reading.js counts syllables by it (Turkish = vowels, English = vowel groups), speech.js spells numbers in it, the voice reads in it.
- `src/core/` — `reading.js` (tokens with times; defaults measured on Buse) and `time.js`, `describe.js` are pure (the window imports them: keep them free of Node imports). `store.js`: project folder, ops, lock, atomic write, `.ccdesk-ui.json` (where the owner is looking). `export.js` (HTML), `state.js` (`~/.config/ccdesk/state.json`: current/recent project + app-wide prefs `appearance {theme, uiFont, scriptFont}`, `uiLanguage` (not used yet), `tts {provider, sync, <provider>: {...}}`; `setPrefs` deep-merges and clamps).
- **Every change is an op through `applyOps(dir, actor, ops)`**; each op returns its inverse (`undo`), which the app uses for undo/redo (the inverse of the inverse is the redo). A new op = a function in `OPS` returning `{id, summary (Turkish), undo}` + `describeOp` + a test; add it to `SUGGESTABLE` if Claude may propose it.
- **Version history** (`core/history.js`, 2026-11-22): `applyOps` records every revision in `<project>/.ccdesk-history/log.jsonl` as `{rev, at, actor, ops, changes}`, where `changes` is a diff of the *normalized* project (scripts/events/suggestions keyed by id, `scriptOrder`, settings, title; no script times — derived — and no timestamps) as `{path, from?, to?}`. `base-<rev>.json` holds a full normalized state where the chain starts or restarts (first change, project from before history, hand edit); opening a project (`startHistory`) writes one so the current revision is comparable. `stateAt(rev)` = latest base ≤ rev + forward `to` values; `diffRevisions(a, b)` reports settings, word-level text diffs, added/removed/moved items, order, and the computed timing (`layout`). MCP: `ccdesk_history`, `ccdesk_diff` (negative revision = back from current). A history write failure is logged, never fails the op.
- `src/main/` — Electron main (ESM), `preload.cjs` (sandboxed bridge `window.ccdesk`), `secrets.js` (API keys, safeStorage-encrypted in `<state>/secrets.json`; never sent to the window), `pty-helper.py` (the terminal: a Python pty bridge, no native module; resize lines on fd 3). The terminal is a plain login shell in the project folder: no AI is started (the owner picks one, 2026-11-22). For an MCP assistant it exports `CCDESK_MCP_CONFIG` (generated mcpServers file for this project; the MCP server runs on Electron's Node via `ELECTRON_RUN_AS_NODE`) and `CCDESK_AGENT_PROMPT` (how to use the tools), both in the state dir; e.g. `claude --mcp-config "$CCDESK_MCP_CONFIG" --append-system-prompt-file "$CCDESK_AGENT_PROMPT"`. Also `CCDESK_MCP_COMMAND` + `CCDESK_MCP_SERVER` for assistants that register servers themselves (`agy mcp add`). **Terminal shortcuts** (`core/shortcuts.js`, `renderer/shortcuts.js`, 2026-11-22): buttons in the terminal header that *paste* a command (xterm `paste`, never run it); global in state.json `terminalShortcuts` (missing = defaults Claude Code + agy), per project in `<project>/.ccdesk-shortcuts.json` (not an op, no history).
- `src/renderer/` — vanilla JS, no build step; xterm.js from `node_modules`.
- Read-aloud is an interface: `src/main/tts/index.js` (`TtsManager`; the provider contract is documented at its top: `check()` → `{supported, ready, reason}`, `signature(lang)`, `speak({text, language, rate, session, out})`, `cancel`, `actions` for its settings pane via `tts:call`). The manager caches by provider + signature + text + rate in `<state>/tts-cache` and refuses unsupported / unready providers; `prefs:set` refuses choosing an unsupported one. Providers:
  - `omnivoice.js`: OmniVoice worker `src/tts/worker.py` (moved from ~/Workspace/ai-test/omnivoice; that venv's Python unless `CCDESK_TTS_PYTHON` / state.json `ttsPython`), a child process speaking JSON lines; queue (one at a time, per-request timeout, cancel by session), restart after a crash (exits on purpose after a CUDA error; 3 deaths in 2 min → rests 1 min), quits after 10 idle min. Supported only with `MIN_SPECS` (NVIDIA GPU ≥ 4 GB via nvidia-smi, ≥ 8 GB RAM) and the Python env. Voices app-wide in `<state>/voices/<id>/` (ref.wav, prompt.pt, meta.json). Every model call inside `torch.inference_mode()` (without it adding a 25 s voice filled the 8 GB GPU).
  - `azure.js`: Azure AI Speech REST (free F0 tier; key in secrets, region + a voice per language in prefs), SSML prosody rate. (Edge's unofficial read-aloud endpoint was rejected: it needs a spoofed client token/origin.)
  - A new provider = a class with that contract, added to the manager's list, plus a pane in `src/renderer/tts/<id>.js` registered in `settings.js` `PROVIDER_PANES`.
- `core/speech.js` (pure) cuts scripts into sentence chunks with timeline times (no [directions], /n breaks, numbers spelled in the content language); the renderer plays chunk by chunk, generating 3 ahead, and moves the playhead over each chunk's audio. Sync to reading speed (`tts.sync`): the renderer learns per voice+language how long the voice takes against the reading model (localStorage `ccdesk.ttsCalibration`), asks the provider for that rate, and closes the rest with `playbackRate` (pitch kept, ±25%) on an `<audio>` element.
- `src/renderer/settings.js` — the settings window (menu left: Görünüm, Dil (empty for now), Sesli okuma; Proje ayarları), applies theme/fonts as `data-theme` / `data-ui-font` / `data-script-font` on `<html>` (CSS vars `--sans`, `--script`).
- `src/mcp/server.js` — `ccdesk_*` tools; `ccdesk_cursor` reads `.ccdesk-ui.json`; `ccdesk_suggest` stores media first, dry-runs the ops (`checkOps`), then adds the suggestion.
- Check: `npm test`; UI: `npm run smoke -- <dir> <out.png> [id] [pps] [time]` (if the SUID sandbox aborts, run `electron . --no-sandbox --smoke …` directly; `CCDESK_STATE_DIR=<tmp>` keeps the real prefs untouched), `CCDESK_SMOKE_JS=<file>` runs a script in the window first (see git history for examples), then look at the PNG.
